# Design — Astro 7 Upgrade

## Approach
Use Astro's official automated upgrade (`pnpm dlx @astrojs/upgrade`) to bump `astro` and the official
integrations (`@astrojs/react`, `@astrojs/mdx`; `@astrojs/rss` already current) together, then verify
build → types → emitted output → RTL spacing → security → perf. Keep config changes minimal — the site
stays fully static (no adapter, no v7 server features). Security advisories are resolved by the version
bump itself. Fix source over masking behavior (prefer `{" "}` in one spot over reverting `compressHTML`).

## Interfaces / files
- `package.json` — astro 7 · @astrojs/react 6 · @astrojs/mdx 7; add `"engines": { "node": ">=22.12.0" }`;
  remove the dead `pnpm.overrides` block (current pnpm ignores it — migrate only if a vuln needs it).
- `pnpm-lock.yaml` — regenerated by the upgrade.
- `astro.config.mjs` — expected no change. `compressHTML: true` is a **fallback only** if RTL spacing regresses.
- `src/layouts/BlogPost.astro` — only if the author line ("מאת: …", ~line 128) loses its space: add `{" "}`.
- Docs (on completion): `docs/tech.md` version table, `docs/decisions.md` (if a choice is made),
  `docs/STATUS.md`, and this spec's `tasks.md`.

## Data touchpoints
None — no schema, content-collection, or data changes.

## Edge cases
- `compressHTML: 'jsx'` collapses whitespace between inline elements → verify BlogPost author line + blog meta row in built HTML.
- Sätteri (new default Markdown processor) rendering differences → eyeball a rendered post body; reinstall `@astrojs/markdown-remark` only if output differs (no remark/rehype plugins are configured, so unlikely).
- Vite 8 + Tailwind v4 compatibility → bump `@tailwindcss/vite`/`tailwindcss` if the build warns.
- esbuild transitive LOW vuln → confirm patched by Vite 8; otherwise add a pnpm override.
- React 19 islands under `@astrojs/react` 6 → confirm Embla + EmailJS hydrate.
- Rust compiler stricter HTML → fix any "unclosed tag" build errors (audit found none expected).

## Test plan (how we'll verify)
- `pnpm build` completes clean; `pnpm exec astro check` reports no new errors.
- Inspect `dist/` for `sitemap.xml`, `robots.txt`, `rss.xml`; grep a built blog post for the intact "מאת: " spacing.
- `pnpm audit` → no HIGH/CRITICAL; confirm the two Astro CVEs are gone.
- **Browser-dependent (chrome-devtools):** Lighthouse parity on `/`, `/blog`, a post; RTL eyeball of Navbar/Footer/blog; island interaction. If the browser MCP is unavailable this session, complete the deterministic checks and record the browser QA as a tracked follow-up before merging to `v3`.
